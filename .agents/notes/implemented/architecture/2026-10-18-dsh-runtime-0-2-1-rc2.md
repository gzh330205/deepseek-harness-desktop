# Agent Note: 随包 DSH 运行时升级到 0.2.1-rc.2（壳 0.4.3）

Status: implemented

> 取代 [2026-10-17-dsh-runtime-0-2-1-rc1.md](2026-10-17-dsh-runtime-0-2-1-rc1.md) 里「升 rc.1、不升 rc.2」的决定：
> 当时拦路的缺包已经发布。

## Problem

随包运行时钉在 dsh `0.2.1-rc.1`，用户发现上游已有更新的 `0.2.1-rc.2`，要求升级。上一轮之所以停在
rc.1，是因为 rc.2 发了一半：`@deepseek-ai/dsh-client-ui-settings-account` 只发到 rc.1，依赖树装不出来
（`ETARGET`）。而 Electron 壳**没有**「DSH 自更新」通道（`settings.ts` 里 `checkDshOnStart` 只是预留），
随包运行时是 app.asar 的一部分，所以「升 DSH」只能走一次新的桌面发版。

## Decision

**`runtime-pin.json` 的 `dsh` 升到 `0.2.1-rc.2`，壳版本升到 `0.4.3`，重跑 `prepare-runtime` 后发布。**

- 缺包已补齐：`@deepseek-ai/dsh-client-ui-settings-account` 现有 `0.2.1-rc.2`；`npm install
  @deepseek-ai/dsh@0.2.1-rc.2 --omit=dev --dry-run` 解析出 612 个包，无 `ETARGET`。
- 上游 0.2.1-rc.2 的用户可见变化（来自 GitHub release `dsh-v0.2.1-rc.2`）：适配
  DeepSeek-V4.1-Flash-1017；适配 DeepSeek Search 与 Fetch API（网页搜索设置里可开启）。
- 升级流程与 0.4.2 相同：改 pin → `prepare-runtime` → 改壳版本 → 再跑 `prepare-runtime`
  （发版闸门比对 `desktop-runtime.json.shell`）→ 全量测试 → 打包 dry-run → 发布。

## 验证

- **依赖完整性**：`npm install @deepseek-ai/dsh@0.2.1-rc.2 --omit=dev --dry-run` 解析出 612 个包，无 `ETARGET`
  （上一轮缺的 `@deepseek-ai/dsh-client-ui-settings-account@0.2.1-rc.2` 已发布）。
- **运行时重建**：`prepare-runtime` 产物 **24,255 个文件 / 545.9 MiB**；裁剪前 711.7 MiB → 457.7 MiB，
  裁剪后 `--version` / `web --help` 正常；`desktop-runtime.json` = `{"shell":"0.4.3","dsh":"0.2.1-rc.2",
  "files":24255,"bytes":572430088}`。
- **测试**：460 条 / 452 通过 / 8 跳过 / 0 失败；`tsc --noEmit` 干净。
- **插件兼容性（rc.2 + 用户真实 profile 副本 + 全新 home）**：主机侧无 `skipping profile bundle`、无 apply 失败
  （仅已知无害的 dbx_mcp JDBC 警告）；客户端页面 `Failed to load plugins: false`；插件 bundle 全部加载——
  `@changfenhuang/dsh-genui` 0.13.0（含 mermaid/three 资源）、`dsh-workspace-category-manager`、
  `dsh-plugin-kit`、`dsh-win-notify`、`dsh-oneway-usage-monitor`；JS console 只有 1 条 Electron CSP 开发警告
  （来自测量用的裸 Electron 窗口，不是应用错误）。rc.1 → rc.2 同线，插件无需改动。
- **发版闸门**：安装包 **223.3 MiB**；打包载荷校验通过（随包运行时 0.2.1-rc.2 / 24,255 文件 / 关键文件 27 个 /
  node 24.18.1 / pnpm 11.7.0）；打包态 smoke PASS（`version: "0.2.1-rc.2"`、`runtime.shell: "0.4.3"`、
  面板插件与 14 个原生工具正常、profile bundles=8）；手机网关 smoke 6 项 PASS；签名自校验通过。
- **APK**：3.4 MiB，包名/版本 1.0.1(2)/minSdk 26/targetSdk 34 与 gradle 声明一致，v2 签名有效，
  sha256 与上一版相同（android 代码未变）。
- **发布后匿名复核**：`latest.json` version=0.4.3（stable）、安装包匿名 HTTP 200、`DSH.Pocket.apk` 匿名
  HTTP 200；Release v0.4.3 四个资产齐全（安装包 223.3 MB、`.sig`、`latest.json`、APK 3.4 MB）。


## Alternatives considered

- **不升，继续用 0.2.1-rc.1**（最强理由：rc.1 已在真机验证过，rc.2 只是两个上游适配，升级要重打 223 MB 安装包
  并让所有已装用户更新）→ 弃：用户明确要求升，且 rc.2 与 rc.1 同属 0.2.1 预发布线、变更面小（适配新版模型与
  Search/Fetch API），升级收益明确。
- **只改 pin 不重跑 prepare-runtime** → 弃：安装包里会是旧运行时配新版本号，`desktop-runtime.json.shell`
  闸门也会拦住。
- **在已安装的应用里手换运行时**（直接把 app.asar 里的 dsh 换掉）→ 弃：运行时在 asar 内、需要 Electron ABI
  的原生模块，手改既不受支持，也会被下一次自动更新覆盖。
- **跳到 npm `latest` 标签** → 弃：`latest` 是 `0.2.0-rc.2`，比已装的 rc.1 还旧；`next` 才是 0.2.1-rc.2。

## Consequences

- 安装包体积随运行时变化，需要重新核对（0.4.2 是 223.3 MB）。
- 已装 0.4.2 的客户端会在下次检查更新时收到 0.4.3；这就是「升级 DSH」的唯一受支持路径。
- 插件兼容性需要重新过一遍：profile 里 8 个第三方插件、`cordis.patch.yml` 引用的 `@deepseek-ai/*` 包、
  以及桌面壳自己的 `dsh-desktop-shell` 注入，都要在 rc.2 上真实启动一次（0.2.1 内部小版本，预期无需改插件）。
