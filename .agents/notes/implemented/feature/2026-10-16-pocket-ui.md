# Agent Note: 手机访问的入口与配置界面（标题栏菜单 + 独立窗口）

Status: implemented

网关本身见 [局域网网关](../architecture/2026-10-16-phone-gateway.md)，公网见
[公网门](2026-10-16-pocket-public-access.md)，手机端见 [Android 客户端](2026-10-16-pocket-apk.md)。
本笔记讲**用户从哪里进入、界面长什么样**，以及两条真机报障查出的 bug。

## Problem

功能做完了，用户找不到、也不敢用：

1. 配置埋在「设置」窗口里，和别的设置混在一起；
2. 扫码连不上：扫出来的地址是 `https://github.com:443/`，而且**改不回来**（每次打开就自动访问那个错地址）；
3. 公网隧道配完了没有任何地方告诉用户「成没成、地址是什么、手机上怎么连」。

## Decision

### 1. 入口在壳自己的标题栏，不在 DSH 里

**我第一版做错了**：把入口做成 DSH 侧边栏的一个图标 + 一个页面（`sidebar.panellist` + `main` 槽），
配置则放在一个独立窗口里。用户指出位置错了——他要的是标题栏里「应用 / 插件」**旁边**的一项。

这不是偏好问题：那条标题栏是**壳自己的 chrome**（`electron/src/titlebar/index.html`，`应用`/`插件` 是它
的两个原生下拉菜单），所以壳自己的功能入口天然属于这里；放进 DSH 侧边栏反而把壳的东西塞进了 DSH 的导航，
还得再解释一遍「这里只是个入口，真正的配置在另一个窗口」。

现在的形状：标题栏加一个 `data-menu="pocket"` 的「手机访问」菜单（`ShellMenuName` 增加 `'pocket'`），菜单项：

- `打开手机访问设置…` → 打开壳自己的手机访问窗口；
- `局域网访问（已开启/已关闭/未运行）` 复选框 → 直接开关，不必开窗口；
- `公网访问（运行中/已关闭）` → **关闭**可以直接点；**开启**会打开窗口，因为免责确认框在那儿，菜单
  放不下那段文字（把确认塞进菜单等于把闸门变成一次误点）；
- `复制局域网地址` / `复制公网地址` → 剪贴板。

好处是常见问题（「现在开着没」「地址是多少」）不用开窗口就能回答。

### 2. 配置界面是一个壳窗口，不是 DSH 页面

`electron/src/pocket-ui/index.html` + `SettingsWindow`（它本就是「壳自有页面窗口」，第二个页面用它开）。
窗口用的是**设置窗口那套现成桥**（`__DSH_SETTINGS__` 的 `get/save/pocket/close`），因此**没有新增任何 IPC
通道**；归属校验从「只认 `/settings/`」改成「认所有壳自有页面」（`SHELL_PAGE_DIRECTORIES`）。

为什么不做成 DSH 页面：网关、隧道、密码都在**主进程**里，DSH 页面要够到它们就得再造一条「页面 → 插件 → 壳」
的命令通道（状态文件 + 命令文件 + 轮询），而窗口用现成的 IPC 就够。少一条通道就少一类「命令丢了/状态不刷新」
的故障。

页面结构（用户要求的三条都在这里）：

| 区域 | 内容 |
|---|---|
| 局域网（同一 WiFi） | 开关、端口、**默认显示连接二维码**、地址、密码（换一个/自定义）、本机地址选择、**刷新二维码**、「手机上怎么连」三步 |
| 公网（不在同一 WiFi） | **状态标签**（未开启/运行中/失败+原因）、快速/命名隧道、本地转发端口、域名与 Tunnel Token、开启（含免责确认）/关闭、运行时的二维码与公网密码、「手机上怎么连」三步、失败时的排查提示 |
| 手机 App | 只有一个「下载手机 App（APK）」按钮；**二维码与下载地址默认隐藏**，点了才展开（用户在真机上装错东西的根源就是这两个码挨在一起） |

设置窗口里对应删掉整段手机访问（只留一句指引），并把表单里提交 `pocketEnabled/pocketPort/pocketTunnel*`
的字段一并删掉——否则在设置页保存一个无关设置就会把网关配置覆盖回去（有静态守卫钉住这两件事）。

## Alternatives considered

- **入口放在 DSH 侧边栏**（最强理由：DSH 侧边栏是用户看会话与插件的地方，入口集中；插件本来就提供插槽
  API，实现成本低。**这就是我第一版的做法**）→ 弃，而且是用户纠正后才想明白的：那条标题栏是壳自己的
  chrome（`应用`/`插件` 都是壳的原生菜单），壳自己的功能入口属于那里；放进 DSH 侧边栏等于把壳的导航塞进
  DSH，还要额外解释「这里只是入口，配置在另一个窗口」。
- **配置做成 DSH 页面**（最强理由：和 DSH 界面一致，不必多开窗口）→ 弃。网关、隧道、密码都在主进程里，
  DSH 页面够不到它们，得再造「状态文件 + 命令文件 + 轮询」这条双向通道；而壳窗口用现成的设置桥
  （`get/save/pocket/close`）**一个 IPC 都不用加**。少一条通道，少一类「命令丢了 / 状态不刷新」的故障。
- **在标题栏菜单里直接开启公网访问**（最强理由：少开一次窗口、少一次点击）→ 弃。开启公网必须过免责确认，
  菜单承载不了那段文字；把确认压成菜单项等于把闸门降级成一次误点。所以菜单只做「关闭」与查看状态，开启
  一律进窗口。
- **两个二维码并列显示**（最强理由：用户一眼看到「连电脑」和「装 App」两个选择）→ 弃。真机上就是这么出事
  的：扫错了码，而且错得毫无提示。下载码收进按钮后面，展开时还写明「用手机相机扫，不是 App 里的扫码」。
- **地址解析继续静默丢弃路径**（最强理由：宽容，扫码结果常常带路径或多余字符）→ 弃。正是这条宽容把
  `https://github.com/.../DSH.Pocket.apk` 变成了「本机地址 `https://github.com:443/`」。拒绝非法输入比
  猜用户的意图更诚实。

## 真机报障查出的两个 bug

### A. 扫「下载 App」的码，被当成了电脑地址

链条是这样的：桌面同时显示两个二维码，用户扫了 GitHub 那个；内置扫码器把 URL 交给
`PocketAddress.normalise`，而它**丢掉路径只留主机**，于是变成 `https://github.com:443/`；接着 `probe()`
把「任何 200」当成「网关说已登录」，而 github.com 确实会回 200；于是 `open()` 把这个**外站地址存进了地址
列表**——此后每次启动都自动打开它，而界面上没有回到编辑器的入口，用户就卡住了。

三处一起修，缺一处都修不干净：

1. `normalise` **拒绝带路径的 URL**（网关地址没有路径；拒绝比静默丢弃诚实），深链接里的 `url` 同样走这条；
2. 网关给**所有响应**加 `X-Dsh-Pocket: 1` 标记头，客户端 `probe()`/`login()` 必须看到它才认——「任何 200
   等于已登录」这条假设本身就是错的，把身份判断交给一个只会由我们发出的标记；
3. 顶栏加「改地址」按钮（任何时候都能回到可编辑的设置面板，不会再被一个错误地址困住），并且探测到「不是
   DSH 入口」时**把该地址从列表里删掉**。

### B. 扫码界面是横屏

`zxing-android-embedded` 自带的 `CaptureActivity` 声明为 `sensorLandscape`。重新声明**那个** activity 会和
清单合并器打架（主题与方向都不同），所以声明一个自己的子类 `PocketCaptureActivity`（`portrait`、同一个
capture 主题）并用 `ScanOptions.setCaptureActivity(...)` 指定它。

## Consequences

- 手机访问的入口与配置**不在设置窗口里**：设置窗口只留一句指引，配置全在「手机访问」窗口里。这与仓库
  原本的「设置只有一个入口」并不冲突——那条规则的目的是**同一项设置不能有两个地方能改**，而手机访问现在
  只有这一个入口（设置页里那一段已经删掉，连带删掉了表单里提交它的字段，并有静态守卫盯住）。
- 菜单里的状态是打开菜单那一刻的快照（`pocketSnapshot()`）；隧道在菜单打开后才变化的话，重开菜单即可看到。
  真正需要实时性的操作都在窗口里，那里每 3 秒刷新一次状态（隧道可能自己死掉：网络变化、cloudflared 退出）。
- 手机端需要**用户手动更新** APK（Android 规则）；这次的 App 修复要等用户扫码重装才生效。

## Evidence

- **应用内**（`DSH_DESKTOP_SMOKE_MENU=1` 的 smoke 驱动，真壳）：`pocket` 菜单**真的打开过**
  （`opened: true`），菜单项为 `["打开手机访问设置…", "separator", "局域网访问（已关闭）", "公网访问（已关闭）",
  "separator", "复制局域网地址（未运行）", "复制公网地址（未运行）"]`；手机访问窗口
  `{"loaded": true, "selectors": {"status": true, "lanQr": true, "wanState": true, "apkToggle": true, "lanEnabled": true}}`
  ——即窗口页面确实渲染完成，关键元素都在（空窗口是这类错误的典型症状）。
  顺带修掉一个 smoke 排序 bug：只写报告的驱动必须在 `finishSmoke()` **之前**跑，否则 `app.exit` 的定时器
  会先到，报告文件永远不出现（看起来像「这个开关没用」）。
- **静态守卫**：`chrome.test.ts` 增加「标题栏每个 `data-menu` 都必须在 `ShellMenuName` 里」——不同步就是
  一个点了没反应、也没有日志的死按钮；`pocket-ui.test.ts` 七条（CSP、元素存在、`[hidden]` 的 grid 陷阱、
  **默认是同 WiFi 连接码**、**APK 默认隐藏且由按钮切换**、**刷新二维码不换密码**、免责确认与 token 不走
  设置保存、三段「手机上怎么连」）；`pocket-ui.test.ts` 还抓到我自己的一处臆测：页面用 `$('id')` 助手，
  守卫最初只认 `getElementById`。
- **预览截图**（`pnpm preview:pocket`，真二维码由 `pocket-qr.ts` 生成）：默认视图只有局域网连接码；点
  「下载手机 App（APK）」后 APK 二维码与地址才出现。
- **手机端单测 21 条**（10 + 11）：新增「带路径的 URL 不是地址」「陌生人的 200 不是电脑」「陌生人的 303
  不是会话」，以及此前的深链接用例。
- 桌面全量测试 451 条 / 444 通过 / 0 失败；`pnpm preview:pocket` 与 `verify-package.mjs` 都覆盖新页面
  （打包时断言 `dist/pocket/index.html` 在 asar 里且引用了桥）。

## 真机（物理手机）实测：结果与两个新发现

用户把手机插上电脑后跑了真机验证（荣耀 JDY-AN00 / Android 14）：

**成功的部分**

- `adb install` 起初被系统拒绝（`INSTALL_FAILED_ABORTED: User rejected permissions`），需要用户在屏幕上允许
  USB 安装；允许后 1.0.1 安装成功。
- 修好的地址解析在真机上生效：深链接里带路径的 GitHub 链接不再变成「电脑地址」，界面报
  「这个链接里没有可用的电脑地址。」并留在可编辑的设置面板。
- **公网整条链路在真机上跑通**：手机用自己的网络打开 `https://<随机>.trycloudflare.com/`，先看到我们的
  「需要访问密码」拒绝页（fail-closed），输公网密码后**完整渲染出 DSH 首页**（鲸鱼、图标栏、「探索未至
  之境」），网关日志 `pocket: [公网] 登录成功，来源 127.0.0.1`（隧道从本机回连）。
- 同一次真机验证还证明了**重启自动恢复**：预置 `accepted: true` 的状态后启动，壳自己把快速隧道拉起来并
  记 `公网访问已恢复：https://…`。

**新发现一：这台手机的系统 WebView 太旧，App 内的界面起不来**

设备的 WebView 是 `com.hihonor.webview 1.0.1.308`（荣耀自带实现），**没通过**能力检测，于是 App 里
「连接」按钮是灰的并提示去更新 WebView。而**同一台手机的浏览器渲染 DSH 完全正常**——说明 DSH 的要求本身
没问题，只是这台设备的系统 WebView 落后。

结论与给用户的话：这台手机现在就能用（**用手机浏览器打开地址**，设置页也写了这条路），APK 要等系统
WebView 更新（应用市场）或换一台 WebView 较新的设备。这个门槛是上一轮加的检测**主动**报出来的，
而不是白屏——那次白屏正是上一轮修掉的问题。

**新发现二（产品缺口）：局域网可达性依赖一条我们的安装器不创建的防火墙规则**

手机与电脑在同一网段、`ping` 也通，但浏览器打不开局域网地址：Windows 防火墙三个配置文件都是开着的，
而入站允许规则 `DSH Desktop` 只覆盖 **Public** 配置文件、且只绑定
`D:\program files\dsh desktop\dsh desktop.exe`（看起来是用户当年允许系统弹窗时留下的，不是安装器建的
——仓库里没有任何防火墙相关代码）。

两点后果：

1. **开发实例**（`node_modules/electron/electron.exe`）不被任何规则覆盖 → 局域网口从别的设备**无法访问**，
   而本机自测（loopback/同机请求）永远看不出这一点。这也是为什么 P1 的「真实网络」验收当年没有暴露它：
   测的都是本机。
2. **全新安装**：如果用户的 WiFi 被判为「专用网络」，那条 Public-only 的规则不生效 → 手机连不上，且没有任何
   提示。

待办（下一轮）：安装器在安装时创建覆盖所有配置文件的入站规则（需要提权），以及壳在局域网口开启后检查
「有没有规则覆盖本程序」，没有就在手机访问窗口里给出说明与一个「允许手机访问（管理员）」按钮（走 UAC）。
在修之前，用户可手动执行一次：

```
netsh advfirewall firewall add rule name="DSH Desktop 手机访问" dir=in action=allow program="D:\Program Files\DSH Desktop\DSH Desktop.exe" protocol=any profile=any
```

### C. 窗口里所有按钮都不起作用（用户实测发现）

窗口能打开、控件都在，点任何按钮（连「关闭」）都没反应。页面自己那行小字就是答案：
「页面未获得桌面壳 API（preload 未加载）」。

根因不是这个页面写错了，而是**壳页面白名单有两份**：加手机访问页时，我改了主进程的 IPC 归属校验
（`/settings/` → 也认 `/pocket/`），却漏了 preload 里的 `isSettingsDocument()`——它写死
`/settings/index.html`，于是 `dist/pocket/index.html` 不注入 `__DSH_SETTINGS__`，页面的所有交互都失去对象。

教训与修法：

- 白名单只能有一份：`SHELL_PAGE_DOCUMENTS`（`constants.ts`），preload 与主进程都读它；静态守卫禁止任何一边
  再出现写死的单页路径。
- **只看元素存在是不够的**：preload 没跑时页面照样把控件画出来，静态页守卫与「元素都在」的探测都会说
  「正常」。smoke 的窗口探测因此新增 `bridge` 字段并断言为真——这类回归现在跑得出来。

## 防火墙：怎么查、怎么放行

`electron/src/pocket-firewall.ts`，两个动作：

- **查**（`probeFirewall`）走 PowerShell 的结构化对象（`Get-NetFirewallApplicationFilter` +
  `Get-NetFirewallRule`），**不解析 `netsh` 文本**——`netsh` 的「规则名称/程序/操作」都是本地化的，解析
  它等于把判定绑到系统语言上。启动局域网口时探一次，结果进 `shell.log`，也进快照给界面。写这段时踩了两个
  必须记下来的坑：
  1. **先按程序筛**。反过来（取全部规则再逐条查 application filter）会做几百次 CIM 调用，实测要几分钟，
     15 秒超时后返回「探测失败」——看起来像「没法检测」，实际上状态是明确的。
  2. **大小写不敏感**。`Get-NetFirewallApplicationFilter -Program` 是**大小写敏感**的字面匹配，而 Windows
     存的是规则创建时的写法（本机是 `d:\program files\dsh desktop\dsh desktop.exe`），程序自己知道的是
     `D:\Program Files\...`：精确匹配命中 0 条，不敏感比较命中 2 条。另外 `JSON.stringify` 生成路径会把
     反斜杠翻倍（`D:\\Program Files\\...`），同样永不命中——这两个都让「已经配好的机器」被报成「没配」。
     测试里钉住了字面量形态与大小写不敏感的写法。
- **放行**（`allowFirewall`）：`Start-Process -Verb RunAs` 起一个提权的 `netsh`，UAC 由用户确认；拒绝或失败
  都会如实返回，界面据此提示，不吞掉。规则是 `protocol=any profile=any`（端口可配置，绑端口号的规则改个
  设置就失效）。

两个入口：**安装器**在 `customInstall` 里尝试建规则（`scripts/installer-bridge.nsh`，卸载时删掉）。正常
渠道是 per-user 安装、**不提权**，所以这一步常常失败——失败只写日志，不当错误；**壳**在局域网口开启后自检，
没有规则就在手机访问窗口里显示说明 + 「允许手机访问」按钮（并在同一处打印可手动执行的 `netsh` 命令）。
两条路都留着的原因：全新安装的普通用户第一次就该能用，而组策略、便携版、拒绝过 UAC 的机器需要事后可修。

## 防火墙修好之后：局域网也在真机上跑通了

修完上面两项后（安装器尝试建规则 + 壳自检/一键放行），同一台物理手机再测一次局域网：

- 放行前：手机浏览器打开 `http://10.1.6.35:41735/` → 「网站暂时无法打开」（`ping` 通、网关自报运行中）。
- 放行后：同一类地址 `http://10.1.6.35:41736/` → 先拿到「需要访问密码」拒绝页，输密码后**完整渲染出 DSH
  首页**，网关日志 `pocket: [局域网] 登录成功，来源 10.1.4.192`——来源是**手机自己的 WiFi 地址**，证明这次
  真的走了局域网，而不是本机回环。
- 壳自己的探测在启动时写进日志：「手机访问：Windows 防火墙已开启，已有入站规则（Public,Public）」/「没有
  覆盖本程序的入站规则」，所以「手机上打不开」现在有第一处可查的地方。

于是两条通道（同一 WiFi / 公网）都有物理手机上的端到端证据，而不是只有本机自测。
