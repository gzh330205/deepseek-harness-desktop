# Agent Note: 手机端的移动布局与传输压缩

Status: implemented

前两半见 [手机访问网关](../architecture/2026-10-16-phone-gateway.md)（局域网）与
[公网门](../feature/2026-10-16-pocket-public-access.md)（隧道）；手机 App 见
[Android 客户端](../feature/2026-10-16-pocket-apk.md)。本笔记只讲**站在手机上看这台电脑的界面**这件事。

## Problem

手机能连上之后，看到的是桌面的界面与桌面体积的传输。两个问题都不该靠想象解决：

- **布局**：窄屏上到底哪里不好用？如果不知道，移植一套「手机布局」很可能是在重做 DSH 已经做对的
  部分，还要在别人的 DOM 上长期维护。
- **体积**：手机走公网/移动网络时，客户端要拉几十个插件 bundle 和一份会话数据。不压缩就是把流量当免费。

## Decision

### 1. 先量，再改（量出来的结论与直觉相反）

做法：在客户端插件里加一段**只在 App 内运行**的视口诊断（`DshPocket` UA 门控），把真实数据打到 console，
用 `adb logcat` 读回来。测的是触发条件而不是猜的条件——**可点区域**按「盒子 + 伪元素撑出的部分」计算，
否则修完也看不到变化。

393×443 CSS 像素（真机尺寸的手机视口）实测，**修复前**：

| 指标 | 实测 |
|---|---|
| 横向滚动 | 无 |
| 超出视口的元素 | 0 |
| 侧栏图标栏宽度 | 36px |
| 可点区域 < 44px 的控件 | **10 个** |

也就是说：DSH 自己的窄屏行为（`SIDEBAR_AUTO_COLLAPSE = 1024`，窄屏把侧栏收成图标栏）**已经处理好了布局**，
没有溢出、没有横向滚动。真正的问题是**触控目标**——左栏 6 个按钮 36×36、右上角 28×28、作曲区的两个下拉与
「+」只有 28px 高。所以不移植任何布局，只补触控尺寸。

`PHONE_CSS`（只在 App 内注入，`@media (max-width: 600px)`）：可点高度补到 44px、图标按钮用伪元素把可点区域
左右各扩 4px、输入框字号 ≥16px、宽内容（`pre`/`table`）自己滚动、`body` 不横向滚。

**修复后**：样本按钮 `min-height` 与 `height` 都变成 44px，不合格控件 **10 → 7**，且**全部控件高度都 ≥44**；
剩下 7 个是 36–42 宽 × 44 高（浏览器面板的标签条按钮、作曲区两个图标按钮）。

关于 `!important`：第一版没加，注入了但**一点没生效**——被 DSH 的设计系统按组件级选择器压住了，指标纹丝不动
才暴露出来。这里覆盖的是别人的设计系统（且只对手机宽度），所以 `min-height` / `font-size` 用 `!important`
是刻意的。但那 7 个按钮的 `::after` 我没有再去 `!important` 覆盖：它们的伪元素属于设计系统自己的视觉层
（涟漪/状态指示），为了 8px 宽度砸掉它不划算——36×44 对手机是可以接受的，这个取舍写在这里而不是藏起来。

### 2. 压缩放在网关，按内容类型而不是按路径

`accept-encoding` 解析（`q=0` 与 `*` 都按语义处理）→ 只压缩文本类（`text/*`、JSON、JS、XML、SVG）、
上游没编码过的、≥1KB 的、非 204/304/HEAD 的响应；压缩时删掉 `content-length`、补 `content-encoding: gzip`
并把 `accept-encoding` 合并进 `vary`（不是覆盖）。

不做**动态字典/Brotli**：Brotli 需要 Node 的 `zlib` 用 brotli 变体（可用），但收益主要在静态资源上，而这个
路径的收益大头是 HTML 与 JSON，gzip 已经覆盖；多一种编码意味着多一条出错路径，而这里是"能用就好"的通道。

## Alternatives considered

- **移植 MIT 的 `dsh-web-mobile` 整套移动布局**（最强理由：现成的手机布局，省事且经过别人的验证）→ 弃。
  实测显示 DSH 自己的窄屏行为已经解决了布局（无溢出、无横向滚动、侧栏自动收成图标栏），而
  `dsh-web-mobile` 是针对**另一套 DSH 界面结构**写的，贴到当前 DOM 上等于在别人的组件树上长期维护第二套
  布局。需要补的只有触控尺寸，用 20 行 CSS 就能做到，且没有版本耦合。
- **靠 UA 之外的判据启用移动样式**（如只按宽度）→ 弃。桌面浏览器窗口缩小也会命中，把桌面的紧凑窗口变成
  手机样式；UA 门控让"这套样式只属于 App"这条边界很清楚。
- **在代理层改 HTML/JS**（注入 viewport 之类）→ 弃。改内容比特意写的 CSS 危险得多，而且 DSH 已经有正确的
  viewport meta。
- **把压缩做成可配置**（最强理由：调试时想看原文更方便）→ 弃。客户端自己声明 `accept-encoding` 就够了，
  多一个开关就多一个"为什么这台机器不一样"的来源。

## Consequences

- 手机上的可点区域不再小于 44px 高；代价是图标按钮的**视觉尺寸仍是 36px**（只有可点区域被扩大），且
  7 个控件的宽度仍不到 44px。
- 传输：DSH 首页 HTML 实测 34,547 → 5,881 字节（**省 83%**），解压后与原文逐字节一致。
- 压缩只作用于网关的明文代理路径，不影响 WebSocket 升级（那是独立路径）与 HTTP 状态码语义。
- 诊断代码留在插件里（只在 `DshPocket` UA 下运行，输出到 console）。它同时是**支持工具**：用户报"手机上
  哪里点不到"时，一条 logcat 就能给出数据。

## Evidence

- **单测**：`pocket-gateway.test.ts` 新增 5 条压缩测试（请求了才压缩、解压逐字节一致、不请求就不压、
  `q=0` 拒绝、小响应/上游已编码/图片不压、`vary` 合并而非覆盖、`accept-encoding` 各种写法），网关共 20 条
  全过。
- **真实测量**（跑在真壳里，从局域网口拉真实资源）：
  `首页 HTML: 34547 → 5881 字节（省 83.0%）encoding=gzip 解压后逐字节一致=true`。
- **手机端实测**（Android 16 模拟器，WebView 133，393×443 视口）：见上表，不合格触控目标 10 → 7，
  全高度 ≥44，且页面无横向滚动。
- 顺带修掉三个 App 端真 bug（都由这次真机驱动发现）：
  1. **深链接的焦点竞态**——`onCreate` 里视图还没布局，`requestFocus()` 被静默丢弃，用户输入的密码会落进
     地址栏。改用 `post()`，并清空上一次残留的密码。修复前同一套操作会随机失败（日志里成对的 401），修复后
     连续两次干净通过。
  2. **一次回车发两次登录**——key event 与 IME action 都触发监听器（日志里两条相隔 6–7ms 的请求），加了 1 秒
     去抖，并只认 `IME_ACTION_DONE` 或 Enter 按下。
  3. **深链接注册缺失**——清单里那条 intent-filter 是补上的（之前 `dshpocket://connect` 无法解析），现在
     `am start -a android.intent.action.VIEW -d "dshpocket://connect?url=…"` 可用。
- 仍然如实的边界：**没有在物理手机上装过**；空置保活只在模拟器网络下观察（真实移动网络的 NAT/省电策略更凶）。
