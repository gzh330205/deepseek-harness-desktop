# Agent Note: 手机访问（局域网 / 公网）+ Android APK 客户端

Status: proposed

## Problem

用户要的是：**人不在电脑前，也能用手机操作电脑上的 DSH**——并且手机上的入口是一个**自己开发的 APK**，不是浏览器书签。

现状与差距：

- 壳的 DSH 服务**只绑 loopback**（`electron/src/host-process.ts` 固定 `--host 127.0.0.1`，端口 `41729`）。这是仓库的硬约束，也是当前访问面的主要防线（DSH 自己的一次性 token + `dsh-auth` cookie 是给本机浏览器用的）。手机要连，无论局域网还是公网，都必须先有**一个新的对外入口**，并重新设计这一层的认证。
- 用户找到一个已实现同类功能的开源项目 **`shaobeichen/dsh-pocket`（v2.11.0，GPL-2.0）**：它是 DSH 插件形态，在 DSH 前面放一个代理（`0.0.0.0:3081` → `loopback:3080`）管访问密码，再挂 cloudflared 隧道出公网，并带一套移动端布局适配。它**能**用于我们的壳（其 README 有一节讲 DSH Desktop），但功能归属在 DSH 插件里，不在壳里。
- 用户明确要求：**参考它、把功能做进我们的壳**，并且手机侧要一个 **APK**。

## Proposal

**已确认的口径（2026-10-16 用户拍板）**：APK 用 WebView 薄壳；**独立实现**（不复制 GPL 代码，仓库保持 MIT；移动布局取 MIT 的 `dsh-web-mobile`）；先做 P1 网关再做 APK；cloudflared **随安装包内置**；移动布局后置到 P4；**局域网访问默认关闭、手动开启**。

三层，逐层可独立验收，**DSH 自身继续只绑 loopback**：

### 1. 壳内访问网关（Electron 主进程）

新增 `electron/src/pocket/`：

- `gateway.ts`：HTTP + WebSocket 反向代理，监听局域网（默认端口 `41730`，可配）。
  - **改头**：入站 `Host` / `Origin` 统一改写成 loopback 权威（`127.0.0.1:41729`），否则 DSH 的 origin 校验会拒。
  - **认证注入**：网关替远程用户满足 DSH 自身的会话认证，远程用户只需要过网关的密码。做法是**复用壳已有的 token→cookie 交换**（`main.ts` 的 `authenticate()`：一次性 token 换 `dsh-auth` cookie，token 不进页面、不进日志）：抽成可复用模块，网关持有一个 **cookie 提供者**（`() => pair | undefined`）而不是自己缓存值 —— **DSH 重启换了 token 后网关自动用新的 cookie**，不需要人工干预。入站 HTTP/HTTPS 都要能工作（隧道侧由 cloudflared 终止 TLS）。
  - **透传**：普通请求与 WebSocket upgrade（DSH 的流式推送）原样透传，保证「电脑上在输出、手机上同步在滚」。
  - **压缩**：大 JSON 响应 gzip/brotli（长会话体积差一个数量级，手机流量与加载速度都受影响）。
- `auth.ts`：两套独立密码 —— **局域网密码**（默认开，可关、可刷新、可自定义 8–64 位）与**公网密码**（默认每次开启轮换，可自定义固定）。
  - **公网判定 fail closed**：除 loopback 与私网网段外，**一切陌生域名/地址（含自建反代指向本机端口）按公网处理、强制公网密码**——不存在「换个域名绕过密码」。
  - **限速**：同一 IP 连续 5 次失败锁 60 秒；全局失败超阈值时短暂全锁（防换 IP 扫描）；成功即清零。
  - 登录状态与 `dsh web` 进程同生命周期：进程不重启则手机免重输（重启/更新后需重输一次）。
- `tunnel.ts`：cloudflared 管理。
  - **随安装包内置**（已确认）：构建期固定版本、校验哈希，产物作为 `extraResources` 打进安装包；运行时只执行随包的那份，**不在运行时下载并执行可执行文件**。`cloudflaredPath` 仍可覆盖（用户想用自己的那份时）。
  - 代价：安装包增大（约 +30 MiB），且 cloudflared 的升级只能随壳发版走。
  - **快速隧道**（随机 `trycloudflare.com` 域名，每次重启变化 = 天然轮换）与**命名隧道**（Tunnel Token + 自有域名，地址固定、密码不轮换）。
  - 壳/DSH 重启后**自动恢复**上次开着的隧道（状态落 `bridgeDir()`）。
  - 停止隧道要**真的停掉子进程**并立即让地址失效。
- `lan.ts`：本机地址枚举（物理网卡优先，虚拟网卡/WSL/VPN 场景可手动选）。
- `qr.ts`：二维码生成（设置窗口里显示，不需要相机权限）。
- `state.ts` / 日志：状态落 `bridgeDir()/pocket.json`，动作写 `shell.log`（沿用现有脱敏规则，**密码与 tunnel token 绝不进日志**）。

### 2. 界面（壳自己的设置窗口）

按仓库既有规则「设置只有一个入口」，手机访问的开关与二维码都放**壳的设置窗口**，新增一节「手机访问」：

局域网开关（**默认关闭**）+ 二维码 + 密码（显示/刷新/自定义）｜公网开关（**每次开启先弹免责声明，勾选后才允许**）+ 二维码 + 密码｜隧道模式（快速/命名 + Token + 固定域名）｜当前地址与状态（隧道是否存活、最近一次错误）｜「复制链接」「打开排查提示」。

**不**往 DSH 设置页里加桌面端设置（既有约定）。

### 3. Android APK（薄客户端）

- **WebView 壳**：首启扫码（相机）或手输「地址 + 密码」；地址与密码存 `EncryptedSharedPreferences`；随后加载的就是网关上的 DSH 页面（与浏览器访问同一套界面、同一套实时同步）。
- 连接管理：保存「局域网地址」与「公网地址」两条，进入时探测可达性并自动选路；不可达时给出**明确原因**（不在同一 WiFi / 隧道没开 / 密码错 / 被限速）而不是白屏。
- 工程细节：`WebView` 开 JS/DOM storage/WebSocket；处理返回键、安全区（刘海/手势条）、文件上传与下载、深色主题、`viewport-fit=cover`；屏幕常亮可选；网络切换（WiFi↔4G）自动重连。
- 构建：Gradle + AGP，用本机 JDK 21 与 Android SDK（本机已有 platforms 34/36.1、build-tools 34/36、license 已接受）。`minSdk 26`，`targetSdk` 跟当前稳定。
- **签名**：新建独立 keystore，私钥不入库（与桌面签名密钥同等管理）；新增环境变量/文档说明其位置。
- 更新：APK 内检查版本 → 读桌面壳的网关状态接口或 GitHub Release 资产；随 Release 分发 `DSH.Pocket_<version>.apk`，由 `release-electron.mjs` 一并上传。

### 4. 移动端布局适配（可以后置）

WebView 里如果直接渲染桌面布局，手机上会很难用。参考项目移植了 `dsh-web-mobile`（MIT）做抽屉式窄屏布局。我们的壳已经会向 DSH 注入自己的客户端插件（`resources/dsh-desktop-shell/client.js`），因此这一步的自然做法是：**在同一个客户端插件里按窄屏/移动 UA 注入移动布局**，而不是再引入第二套插件。

## Alternatives considered

- **直接装 `dsh-pocket` 插件**（零开发量）：最强理由是它就是成品——109 个测试、LAN/公网/密码/限速/隧道/移动布局全有，作者还专门适配了 DSH Desktop。不采用的原因：① 用户要的是**壳内**实现（设置入口、端口/配置/更新体系与桌面壳打通，而不是在 DSH 里多一个第三方设置页）；② 它是 **GPL-2.0**，我们的仓库是 MIT（见 Risks）；③ 它的代理端口、密码文件、隧道进程都自成一套，和壳自己的状态与日志体系并行，出问题时要跨两套系统排查。
- **让 DSH 直接绑 `0.0.0.0`**：最强理由是改动最小（一行 `--host`），局域网立刻可用。放弃原因：破坏仓库硬约束（loopback 是当前访问面的主要防线）；公网暴露后只剩 DSH 自己的 token/cookie，没有独立密码、没有限速与失败锁、也没有「公网/局域网两套凭据」的隔离面。
- **APK 用原生 Compose 重写 DSH 界面**：最强理由是体验最好（原生滚动、离线缓存、原生通知）。放弃原因：等于长期分叉 DSH 的 UI 与客户端协议（DSH 每次升级都可能破），工作量比 WebView 壳高一个数量级，而用户要的核心是「手机能操作电脑上的 DSH」。
- **APK 用 TWA / PWA**：最强理由几乎是零成本。放弃原因：TWA 要求固定域名 + `asset links`，与快速隧道的随机域名不兼容；PWA 仍需要用户在浏览器里操作安装，不是「一个 APK」。
- **只做浏览器访问、不做 APK**：用户明确要 APK，不采用。
- **首次使用时下载 cloudflared**：最强理由是不必为永远不开公网的用户增大包体，而且 cloudflared 能独立升级、不必跟着壳发版。**未采用**：在用户机器上运行期下载并执行一个第三方二进制，等于把供应链风险放在最不可控的时刻发生；随包内置让「到底执行了哪份二进制」在构建期就确定、可校验、可复现。包体代价（约 +30 MiB）与升级节奏变慢，由发版流程承担。

## Acceptance criteria

- **局域网**（需先在设置里开启；默认关闭）：手机与电脑同一 WiFi，扫码 → 输一次密码 → 打开的就是电脑上的 DSH；流式输出双向实时；超时/断线自动重连。
- **公网**：设置页确认免责后开启隧道 → 拿到可在 4G 下访问的地址；关闭后地址立即失效；公网密码错 5 次锁 60 秒；**任何非私网 Host 都强制公网密码**（换域名/自建反代绕不过）。
- **DSH 自身仍只监听 `127.0.0.1:41729`**：`netstat` 可断言；对外只有网关端口。
- **APK**：Android 8.0+ 可安装；扫码或手输地址 + 密码进入同屏界面；杀进程重开免重扫；地址不可达时给出具体原因；文件上传/下载、返回键、安全区正常。
- **发版**：`release-electron.mjs` 产出并上传 APK；桌面 smoke 覆盖网关（起网关 → 断言 upstream 是 loopback、密码校验、失败锁、`Host` 改写）。

## Risks

- **公网暴露面**：DSH 能在电脑上执行代码，公网可达＝把执行权限挂到互联网。缓解：默认关闭、密码强制（不提供 `--no-auth`）、失败锁、fail-closed 公网判定、每次开启的免责闸门、UI 常驻「用完请关闭」提示。
- **GPL 污染**：`dsh-pocket` 是 GPL-2.0，本仓库是 MIT。读它取**行为与取舍**可以，**不能抄代码表达**；移动布局若要移植，应取 MIT 的 `dsh-web-mobile`（参考项目也是从那里移植的）。若最终决定复用它的代码，则必须把相应部分隔离为 GPL 子包或整体换 GPL-2.0 —— 需要用户明确选择。
- **cloudflared 供应链**：下载即执行。必须校验（哈希/签名），并允许用户指定自带的 `cloudflaredPath` 跳过下载；镜像源不可信时宁可失败也不执行。
- **代理/VPN 干扰**：本机开着 TUN 模式代理（Clash 等）时隧道常见 `error 1033`。UI 必须内建这条排查提示（参考项目 README 有一节专讲）。
- **壳的加载模式**：`advanced` 模式禁用网页布局，手机端会白屏。设置页要在开启手机访问前检测并阻止/提示。
- **长连接存活**：手机省电策略会掐 WebSocket。需要心跳 + 自动重连；若实测仍频繁断，再考虑前台服务（会带来常驻通知）。
- **APK 签名密钥**：丢失即老版本无法升级（与桌面 NSIS 密钥同等严重）。需要与桌面密钥分开存放并写进文档。
- **隧道子进程生命周期**：壳崩溃/退出时要确保 cloudflared 与网关被回收，不能留下裸奔的公网入口。
