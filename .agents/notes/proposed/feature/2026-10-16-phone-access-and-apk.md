# Agent Note: 手机访问后续阶段（公网隧道 + 移动布局 + 发版）

Status: proposed

> - 局域网网关（P1）已落地：[implemented: 手机访问网关](../../implemented/architecture/2026-10-16-phone-gateway.md)
> - Android 客户端（P2）已落地：[implemented: Android 客户端](../../implemented/feature/2026-10-16-pocket-apk.md)
>
> 本笔记只覆盖**尚未开工**的部分：公网隧道（P3）、移动布局与保活（P4）、发版集成（P5）。

## Problem

- **人不在同一 WiFi 时用不了。** 现在只有局域网入口。需要一条公网通道，而它把「能在你电脑上执行代码的
  DSH」暴露到互联网——认证、关闭方式与免责确认必须是产品级的一部分，不能是附赠品。
- **手机上渲染的是桌面布局**，窄屏难用（侧栏挤占、触控目标过小），长会话的大 JSON 响应在移动网络上也很重。
- **发版时要把 APK 一起交付**：现在 release 只传 Windows 安装包 + 签名 + `latest.json`。

## Proposal

### P3 公网隧道（cloudflared，随包内置）

- **第二个监听器**：`127.0.0.1:<tunnel-port>`，只给 cloudflared 回连。到达它的流量**按定义是公网**，
  强制公网密码——不靠判定 Host/IP 猜。这是 P1 已经确立的形状（局域网口与隧道口分开）。
- **随安装包内置 cloudflared**（已确认）：构建期固定版本、校验哈希，作为 `extraResources` 打包；运行时只
  执行随包的那份，**不在运行时下载可执行文件**。`cloudflaredPath` 仍可覆盖。代价：安装包约 +30 MiB，
  升级随壳发版。
- **两种隧道**：快速隧道（随机 `trycloudflare.com` 域名，每次重启变化＝天然轮换）与命名隧道
  （Tunnel Token + 自有域名，地址固定、密码不轮换）。
- **免责闸门**：每次开启公网前必须勾选确认（服务端强制校验），设置页常驻「用完请关闭」提示。
- **自动恢复**：壳/DSH 重启后重新拉起上次开着的隧道（状态落 `bridgeDir()`）。
- **子进程回收**：壳退出/崩溃时 cloudflared 必须被收掉，不能留下裸奔的公网入口。

### P4 移动布局与体验

- 窄屏抽屉布局（移植 **MIT** 的 `dsh-web-mobile`），注入我们**已有的**客户端插件
  （`resources/dsh-desktop-shell/client.js`），不引入第二套插件。手机端已经会把
  `DshPocket/1.0` 附在 User-Agent 里，可据此只在 App 内启用。
- 大 JSON 响应的 gzip/brotli（长会话体积差一个数量级）、心跳保活与断线重连。

### P5 发版集成

- `release-electron.mjs` 产出并上传 `DSH.Pocket_<version>.apk`，APK 内做版本检查。
- 打包态 smoke 扩展：现有 `scripts/smoke-pocket.mjs` 已覆盖网关；再加隧道与 APK 资产的存在性断言。

## Alternatives considered

- **首次使用时下载 cloudflared**：最强理由是不为永不开公网的用户增大包体，且 cloudflared 能独立升级。
  **未采用**：在用户机器上运行期下载并执行第三方二进制，等于把供应链风险放在最不可控的时刻发生。
- **让用户自己装 cloudflared**：最强理由是零供应链责任。放弃原因：开箱即用性最差，而这是「手机访问」的
  核心卖点。
- **公网/局域网共用一个监听器、靠 Host 判定区分**：最强理由是少一个端口、少一份状态。放弃原因：判定出错
  就是把公网密码绕过去（参考项目为同类问题打过 fail-closed 补丁），而两个监听器让这件事在结构上不可能。
- **让手机端自己连 DSH 的 loopback 服务**：不可行（也不该可行）——这正是网关存在的理由。

## Acceptance criteria

- **公网**：设置页确认免责后开启隧道 → 拿到可在 4G 下访问的地址；关闭后地址立即失效；公网密码错 5 次锁
  60 秒；任何经隧道到达的请求都强制公网密码。
- **隧道二进制**：`verify-package` 断言随包里存在 cloudflared 且哈希与固定版本一致；缺失即打包校验失败。
- **移动布局**：窄屏下侧栏变抽屉、会话全宽、不出现横向滚动条；长会话响应被压缩。
- **发版**：release 脚本上传 APK，`latest.json` 与 APK 版本一致。

## Risks

- **公网暴露面**：DSH 能在电脑上执行代码。缓解：默认关闭、公网必须显式开启 + 免责确认、强密码、失败锁、
  用完即关提示、壳退出即收回隧道。
- **cloudflared 供应链**：随包内置把风险移到构建期，因此**构建期必须校验哈希**并记录版本来源。
- **本机代理/VPN 干扰**：开着 TUN 模式代理（Clash 等）时隧道常见 `error 1033`。UI 必须内建这条排查提示
  （参考项目 README 有一节专讲）。
- **壳的加载模式**：`advanced` 模式禁用网页布局，手机端会白屏；开启手机访问前要检测并阻止/提示。
- **长连接存活**：手机省电策略会掐 WebSocket，需要心跳 + 自动重连；若实测仍频繁断，再考虑前台服务
  （会带来常驻通知）。
- **GPL 边界**：读 `dsh-pocket` 取行为与取舍可以，**不能抄代码表达**；移动布局若移植，取 MIT 的
  `dsh-web-mobile`。
