# Agent Note: 手机访问后续阶段（公网隧道 + Android APK + 移动布局）

Status: proposed

> 局域网网关（P1）已落地，其设计、取舍与实测证据见
> [implemented: 手机访问网关](../../implemented/architecture/2026-10-16-phone-gateway.md)。本笔记只覆盖**尚未开工**的部分。

## Problem

- **人不在同一 WiFi 时用不了。** 现在只有局域网入口；用户要的是「在外面也能掏手机看电脑上的 DSH」，
  这需要一条公网通道，并且这条通道把「能在你电脑上执行代码的 DSH」暴露到互联网，认证与关闭方式必须是
  产品级的一部分，而不是附赠品。
- **手机端入口要是一个 APK**，不是浏览器书签：用户明确要求自己开发一个能装在手机上的客户端。
- 手机屏幕上是桌面布局，直接渲染会难用；以及发版时要把 APK 一起交付。

## Proposal

**已确认的口径（2026-10-16 用户拍板）**：APK 用 **WebView 薄壳**；**独立实现**（不复制 GPL 代码，
仓库保持 MIT；移动布局取 MIT 的 `dsh-web-mobile`）；cloudflared **随安装包内置**；移动布局后置；局域网
默认关闭（已在 P1 落地）。

### P2 Android APK（WebView 薄壳）

- 原生层只做浏览器做不了/做不好的事：**扫码**（相机）与手输「地址 + 密码」、把凭据存
  `EncryptedSharedPreferences`、局域网与公网两条地址的**可达性探测与自动选路**、断网/切网自动重连、
  返回键与安全区、文件上传下载、深色主题。界面本身仍是 P1 网关上的 DSH（与浏览器同一套，实时同步）。
- 不可达时给**具体原因**（不在同一 WiFi / 隧道没开 / 密码错 / 被限速），而不是白屏。
- 构建：Gradle + AGP，用本机 JDK 21 与 Android SDK（已确认本机具备：platforms 34/36.1、build-tools 34/36、
  license 已接受）。`minSdk 26`。
- 新签名 keystore，私钥不入库（与桌面签名密钥同等管理）。

### P3 公网隧道（cloudflared，随包内置）

- **第二个监听器**：`127.0.0.1:<tunnel-port>`，只给 cloudflared 回连。到达它的流量**按定义是公网**，
  强制公网密码——不是靠判定 Host/IP 猜（P1 已用两个监听器确立这个形状）。
- **随安装包内置 cloudflared**：构建期固定版本、校验哈希，作为 `extraResources` 打包；运行时只执行随包的
  那份，**不在运行时下载可执行文件**。`cloudflaredPath` 仍可覆盖。代价：安装包约 +30 MiB，升级随壳发版。
- **两种隧道**：快速隧道（随机 `trycloudflare.com` 域名，每次重启变化＝天然轮换）与命名隧道
  （Tunnel Token + 自有域名，地址固定、密码不轮换）。
- **免责闸门**：每次开启公网前必须勾选确认（服务端强制校验），且在设置页常驻「用完请关闭」提示。
- **自动恢复**：壳/DSH 重启后重新拉起上次开着的隧道（状态落 `bridgeDir()`）。
- **子进程回收**：壳退出/崩溃时 cloudflared 必须被收掉，不能留下裸奔的公网入口。

### P4 移动布局与体验

- 窄屏抽屉布局（移植 **MIT** 的 `dsh-web-mobile`），注入我们**已有的**客户端插件
  （`resources/dsh-desktop-shell/client.js`），不引入第二套插件。
- 大 JSON 响应的 gzip/brotli（长会话体积差一个数量级）、心跳保活与断线重连。

### P5 发版集成

- `release-electron.mjs` 产出并上传 `DSH.Pocket_<version>.apk`；APK 内做版本检查。
- 打包态 smoke 覆盖网关与隧道（桌面侧已有 `scripts/smoke-pocket.mjs` 可扩展）。

## Alternatives considered

- **APK 用原生 Compose 重写 DSH 界面**：最强理由是体验最好（原生滚动、离线缓存、原生通知）。放弃原因：
  等于长期分叉 DSH 的 UI 与客户端协议，DSH 每次升级都可能破，工作量比 WebView 薄壳高一个数量级。
- **APK 用 TWA / PWA**：最强理由几乎是零成本。放弃原因：TWA 要求固定域名 + `asset links`，与快速隧道的
  随机域名不兼容；PWA 仍需用户自己在浏览器里操作安装，不满足「一个 APK」。
- **首次使用时下载 cloudflared**：最强理由是不为永不开公网的用户增大包体，且 cloudflared 能独立升级。
  **未采用**：在用户机器上运行期下载并执行第三方二进制，等于把供应链风险放在最不可控的时刻发生。
- **让用户自己装 cloudflared**：最强理由是零供应链责任。放弃原因：开箱即用性最差，而这是「手机访问」的
  核心卖点。
- **公网/局域网共用一个监听器、靠 Host 判定区分**：最强理由是少一个端口、少一份状态。放弃原因：判定出错
  就是把公网密码绕过去（参考项目为同类问题打过 fail-closed 补丁），而两个监听器让这件事在结构上不可能。

## Acceptance criteria

- **公网**：设置页确认免责后开启隧道 → 拿到可在 4G 下访问的地址；关闭后地址立即失效；公网密码错 5 次锁
  60 秒；**任何经隧道到达的请求都强制公网密码**（结构与判定双重保证）。
- **隧道二进制**：`verify-package` 断言随包里存在 cloudflared 且哈希与固定版本一致；缺失即打包校验失败。
- **APK**：Android 8.0+ 可安装；扫码或手输地址 + 密码进入同屏界面；杀进程重开免重扫；地址不可达时给出
  具体原因；文件上传/下载、返回键、安全区正常。
- **移动布局**：窄屏下侧栏变抽屉、会话全宽、不出现横向滚动条。
- **发版**：release 脚本上传 APK，`latest.json` 与 APK 版本一致。

## Risks

- **公网暴露面**：DSH 能在电脑上执行代码。缓解：默认关闭、公网必须显式开启 + 免责确认、强密码、
  失败锁、用完即关提示、壳退出即收回隧道。
- **cloudflared 供应链**：随包内置把风险移到构建期，因此**构建期必须校验哈希**并记录版本来源。
- **本机代理/VPN 干扰**：开着 TUN 模式代理（Clash 等）时隧道常见 `error 1033`。UI 必须内建这条排查提示。
- **壳的加载模式**：`advanced` 模式禁用网页布局，手机端会白屏；开启手机访问前要检测并阻止/提示。
- **长连接存活**：手机省电策略会掐 WebSocket，需要心跳 + 自动重连；若实测仍频繁断，再考虑前台服务
  （会带来常驻通知）。
- **APK 签名密钥**：丢失即老版本无法升级（与桌面 NSIS 密钥同等严重），需与桌面密钥分开存放并写入文档。
- **GPL 边界**：读 `dsh-pocket` 取行为与取舍可以，**不能抄代码表达**；移动布局若移植，取 MIT 的
  `dsh-web-mobile`。
